## CI local y administración GitHub

La política operativa vigente es **CI exclusivamente local**. Tras activar un
entorno Python 3.12 con `mypy==1.19.1` disponible, los comandos canónicos son:

```sh
python -m unittest discover -s tests -p 'test_*.py'
python -m mypy --strict src/
python scripts/fuzz_diferencial.py
python scripts/fuzz_admision.py
EKTEL_VECTORS_OUT=<directorio-temporal> python scripts/generate-golden-vectors.py
diff -r contracts/vectors/v1 <directorio-temporal>
git diff --check
```

GitHub conserva un único workflow versionado, `.github/workflows/ci-m1.yml`,
como especificación auditable. El workflow `ci-m1`, ID `340058300`, quedó en
estado remoto `disabled_manually` mediante `gh` con permiso `ADMIN`; no debe
reintentarse ni usarse como gate mientras esta política esté vigente.

La corrida de publicación
`https://github.com/kristhianmanue1/ektel/actions/runs/33222998892` no ejecutó
pasos (su único job registró `steps=[]` y `runner_id=0`) y fue bloqueada por
pagos fallidos o límite de gasto. Se conserva como evidencia de
infraestructura, no como fallo o éxito del código.

## Riesgo residual aceptado

`src/domain/capability.py::_finite_float()` puede propagar una excepción de una
subclase numérica hostil si `verify_capability()` se invoca directamente. No se
demostró ruta end-to-end desde `AdmissionService`, que exige tipos exactos en
reloj y configuración antes de llamar al dominio. Se clasifica P3 de defensa en
profundidad y no bloquea M1-R1.

Persisten además los límites ya declarados: el timeout de `PolicyPort` es
post-hoc y no cancela un adaptador bloqueado; el nonce se quema antes de
política conforme a ADR-004; no existe proceso real, supervisión ni auditoría
M2/M3.

## Decisión y límites

**M1-R1 queda cerrado administrativamente.** M1 conserva su cierre previo y la
corrección publicada pasa a ser su estado vigente.

Este cierre:

- no autoriza M2 ni M3;
- no autoriza tag ni release antes del cierre de M3;
- no convierte el borrador de handoff en ADR aceptada;
- no convierte GitHub Actions en fuente de evidencia;
- no autoriza reactivar `ci-m1` ni agregar otro workflow remoto.

El siguiente trabajo posible es una ADR previa a M2 para resolver el handoff
`admit → start`; requiere una instrucción separada y no comienza por efecto de
esta acta.
